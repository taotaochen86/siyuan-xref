# 图表公式交叉引用（siyuan-xref）

自动重排当前文档的**图 / 表 / 公式**编号，并同步刷新全文交叉引用。

**English**: see [README_en.md](./README_en.md).

安装：思源「设置 → 集市 → 插件」里搜索「图表公式交叉引用」或 `xref` 即可安装。

## 自动还是手动

**默认自动**：你写完题注、停手约 1.5 秒，插件自动重排编号并刷新引用，不弹提示。

不会打断你输入的三种保护：

1. 光标停在待改的块里 → 只有**这个块 4 秒内刚被你改过**才等；光标只是停在那儿不算，照常执行（实测：删块后光标会落在相邻块，早期版本因此卡住不动，v0.2.1 已修）
2. 插件自己写入产生的变更 → 4 秒静默窗口，不会自激
3. 写完不弹窗，出错只在控制台留 `[siyuan-xref]` 日志

想彻底关掉：设置里取消「自动重排」，改用 `/xrefnum` 手动触发。

## 用法

在编辑器里输入 `/`，然后输入下面任一触发词：

| 触发词 | 作用 |
|---|---|
| `/xref` `/交叉引用` `/图ref` | 弹出本文档的图表公式清单，↑↓ 选择、回车插入引用 |
| `/xrefnum` `/重排编号` `/图表编号` | 立刻重排当前文档全部编号，并刷新已有引用 |

设置入口：思源「设置 → 集市 → 已下载 → 图表公式交叉引用 → 设置」。

## 快捷键

| 动作 | 默认键 | 在哪儿改 |
|---|---|---|
| 插入交叉引用 | `Ctrl+Alt+R` | 插件设置里点「自定义快捷键 → 插入交叉引用」，直接按下想要的组合键 |
| 重排图表编号 | `Ctrl+Alt+N` | 同上，第二格 |

- 组合键**必须带 Ctrl / Alt / ⌘**（单键容易被打字误触发，插件直接不录）。`Backspace` 清空，`Esc` 取消。
- 录完立刻生效并写进 `settings.json`，不用重载插件。
- 同样的两个动作也注册成了**原生命令**，会自动出现在「设置 → 快捷键 → 插件 → 图表公式交叉引用」里，习惯用思源统一键位管理的可以在那里改；两处都设了同一个键也只会执行一次（400ms 去重）。
- 输入框、搜索框、设置面板里不响应，不会抢你输字。中文输入法组字过程中也不响应。

## 性能与稳定性（v0.9.0）

| 项 | 以前 | 现在 |
|---|---|---|
| 长文档块数 | SQL 默认只回 **64 行**，超过就静默截断，图注漏编 | 查询加 `limit -1`，实测 348 块全量 |
| 采集一次块清单 | 逐块问 `getChildBlocks`，348 块要 **349 次往返 / 1.5 秒** | 1 次 SQL + 1 次 `getDoc` 定顺序，**约 0.33 秒、2 次往返** |
| 全局网络探针 | 无条件挂钩 `window.fetch`，每个请求都 clone 响应 | **默认不装**，只在「诊断日志」开启时装 |
| 重入 | 自动轮与手动轮可能同时写同一个块 | `_running` 保护，手动轮提示「正在重排」 |
| 长会话内存 | `_editAt` 只增不减 | 每 200 次编辑回收一次 60 秒前的记录 |
| Lute 实例 | 每改一个块新建一个 | 复用同一个 |

块顺序怎么来的：一次 `getDoc` 拿整篇 HTML，块在 HTML 里出现的先后就是文档顺序。已用 68 篇真实文档（2~348 块）逐一比对过「逐块 `getChildBlocks` 递归」的结果，**顺序完全一致**；`getDoc` 整篇失败时自动退回老路径。

## 三条约定（照做才不会乱）

1. **题注写成独立段落**：`图 2 稻田水位示意`。表格块内部塞不进编号。重排时会顺手把这行设为**居中 + 浅底色**。
2. **公式编号写进 `\tag`**：`$$ … \tag{2} $$`，插件会自动维护。
3. **引用用双引号**：`((块ID "图 2"))`。不要用单引号——单引号是「动态锚文本」，导出成 Word/PDF 时会被替换成定义块全文，公式引用会变成一大串 LaTeX 源码。

## 设置项

| 项 | 默认 | 说明 |
|---|---|---|
| 编号模式 | 全文连续 | 全文连续（图 1、图 2）/ 按章（按文档最浅的标题级别换章，图 1-1、图 2-1） |
| 图 / 表 / 式 标签 | 图 / 表 / 式 | 题注前缀文字，可改成 Figure / Table / Eq |
| 重排时同步刷新引用 | 开 | 关闭后只改编号，不动已有引用 |
| 自动重排 | 开 | 停手 1.5 秒后自动生效，不写入光标所在块 |
| 失效引用怎么处理 | 转成红色删除线文本 | 见下文「删掉图表/公式之后」 |
| 题注居中 | 开 | 图 / 表题注段落自动设为居中（公式块本身居中，不设） |
| 题注底色 | 浅 | 给题注加一层很淡的底色：无 / 极浅 / 浅 / 浅蓝。用半透明灰，暗色主题下也是浅色，不会压住文字 |
| 自定义快捷键 | Ctrl+Alt+R / Ctrl+Alt+N | 点输入框后按下组合键即录制；见上文「快捷键」 |
| 诊断日志 | 关 | **排查问题才开**：开启后拦截全局网络请求并写 `ws-log.json`。平时开着会拖慢思源 |

## 识别规则

- 块属性 `custom-xref = fig | tab | eq` → 按属性归类（最可靠）
- 公式块自动归「式」
- 段落以 `图 N` / `表 N` / `Figure N` / `Table N` 开头 → 归图或表
- 段落写「式 N …」不参与编号（公式编号由 `\tag` 承载，避免重复计数）

## 删掉图表/公式之后

实测（v0.2.1）：删块后 **4 秒内**编号自动前移，引用跟着改。

| 场景 | 结果 |
|---|---|
| 删中间的图 | 后面的图号整体前移，正文里的引用同步改成新号 ✅ |
| 删第一个公式 | 后面的公式 `	ag` 前移 ✅ |
| 删末位的图 | 前面编号不动，无多余改写 ✅ |

但有一件事要处理：删除块后，思源会把原来引用它的地方变成
「孤儿文字」——`((已删id "图 2"))` 里的目标没了，正文里就剩下一个孤零零的「图 2」。
这个死引用会让思源反复报「未找到块」，而且它和新编号会撞车，读起来像重复。

v0.5.0 起默认**把它转成普通文字**，但保留**红色 + 删除线**（`~~…~~` 叠 `color:var(--b3-font-color1)`，
思源会归一化成一个 `<span data-type="s" style="color:…">`，一行同时带删除线和红字）：

```
删掉原「式 1」后
  式 1  y = A×sin(x)          ← 原式 2 顺延上来，编号正常
  见 式 2                      ← 原式 3 的引用，已同步成新号
  见 ~~式 1~~（红）             ← 指向已删块，已转成文本，不再报错
```

- 转成文本后**引用关系就没了**（这正是消除报错的原因），原 markdown 会存进
  `data/storage/petal/siyuan-xref/dead-fix-log.json`（最近 60 条），要手工恢复可以查
- 不想失去引用关系就把设置改成「仅标红，保留引用」：只加红字+删除线，块撤销恢复后自动复原
- 自动模式下转换后会弹一次提示告知数量

> 实测记录（v0.4.0 开发过程中发现）：`/api/block/updateBlock` 重写含死链引用的段落时，
> 思源的 markdown 解析器会把 `((已删id "式 1"))` **直接降级成纯文本**（DOM 变 `data-type=""`、
> 无 `data-id`）。所以「保留引用同时改锚文本」这条路走不通，要么保留原样（仅标红），要么彻底转文本。

## 为什么图 2 变成了「孤儿」

因为思源本身**不维护引用文本**：`((id "图 2"))` 里的「图 2」是插入当时写死的静态字符串，
改块的 `name` 不会让引用自动跟随。跨文档、跨设备、导出时都不会变。这就是这个插件存在的原因。

## 为什么写块内容要用 DOM 模式

块的属性（`name` / `style` / `custom-xref` / 你自己加的 `memo`、颜色…）全部挂在块根节点的
HTML 属性上。`/api/block/updateBlock` 用 `dataType: "markdown"` 时会**拿 markdown 重建整块，
把根节点的属性全部丢掉**；用 `dataType: "dom"` 回传则原样保留。

所以 v0.6.0 起改成：先取当前块 DOM（带着全部属性）→ 用 Lute 把新 markdown 转成块 DOM →
**只把内容节点搬进旧根节点，根节点不动** → `dataType: "dom"` 写回。

```
旧: <div data-node-id="A" name="图 1" style="text-align: center;"> … </div>
新: <div data-node-id="?" data-type="NodeParagraph"> 图 2 … </div>
        ↓ 只搬内容，根节点沿用旧的
写回: <div data-node-id="A" name="图 1" style="text-align: center;"> 图 2 … </div>
```

拿不到 Lute 时才退回 markdown 模式，并在写完内容后统一补属性。

## 公式是怎么改的（不会丢正文）

公式正文存在块根节点的 `data-content` 属性上，不在子节点里，所以它跟普通段落完全不同。
插件对公式走一条专用路径：

1. 取回该块当前的 DOM
2. 只把 `data-content` 里的 `\tag{…}` 换掉
3. 原样写回

**不经过 Lute、不重建块、不碰子节点**，所以公式正文不可能被覆盖。同时它是拿内核里的真身来算的，
不受 `blocks` 表索引延迟影响。

三道保险：

- **空公式不编号**：公式体为空（或只剩 `\tag`）就不写编号。否则会造出 `$$\n\tag{1-4}\n$$` 这种只剩编号的块，
  而且它每次都会被再写一遍、永远修不回来。这类块思源还不索引，会从搜索和大纲里消失。
- **正在敲公式时整轮跳过**：公式编辑器一有焦点，这一轮直接放弃，等你写完再说。
- **写回前比对长度**：新内容比旧内容短掉四成以上，判定为采集到了半截内容，放弃这次写入。

## 构建与发布（开发者）

### 发版前必须改的信息

| 项 | 位置 | 说明 |
|---|---|---|
| `version` | `plugin.json` **和** `package.json` | 两处都要改，只改一处会被 `preflight` 拦下 |
| `url` | `plugin.json` | 必须是真实仓库地址，**不能留 `OWNER` 占位符** |
| `description` | `plugin.json` 的 `default` 与 `zh-CN` | 把本次新增的能力写进去，两种语言同步 |
| `displayName` / `keywords` | `plugin.json` | 有新功能就补关键词 |
| `readme` 指向的文件 | `README.md` / `README_en.md` | 集市会把它们当详情页正文渲染 |
| `minAppVersion` | `plugin.json` | 必须是思源真实存在的版本号 |

`url` 尤其关键：集市详情页的**包名链接取 `repoURL`，作者链接取 `repoURL` 里的 owner**，`author` 字段只负责显示文字、不参与链接。写成 `OWNER` 会让两个链接同时 404。

### 发版步骤

```bash
bash scripts/preflight.sh          # 体检：占位符 / url 一致性 / 版本 / zip 结构，不过就退出
git add -A && git commit -m "release: vX.Y.Z" && git push origin main
GH_TOKEN=ghp_xxx bash scripts/release.sh [发布说明.md]   # 内部会再跑一次 preflight
bash scripts/deploy.sh             # 本地重装验证（必须在占位符替换之后）
```

其他命令：

```bash
npm run check    # 语法 + 清单校验
npm run build    # 生成 package.zip（文件在 zip 根层，不套目录）
npm run release  # 打 Release 并上传附件
```

集市只认 GitHub **Latest Release** 里的 `package.zip`。首次收录需向 `siyuan-note/bazaar` 提 PR 在 `plugins.txt` 追加一行；**之后每次更新只改 `version` 再发 Release 即可，不用再提 PR**，索引一到三小时内自动更新。


## 已知限制

- 只能处理当前打开的文档，不跨文档
- 表格块本身不写编号，靠上下方的题注段落承载
- 重排会改写块内容，块历史记录里会多出若干条（可在文档历史回滚）
- 自动重排改写块时会计入撤销栈：写完立刻按 `Ctrl+Z` 撤到的可能是插件的改动，不是你的输入。介意就在设置里关掉自动
- 光标停在待改的块里时会一直等，所以**边写边看编号不变是正常的**，移开光标即生效
- 大概停手 8 秒后才写（`EDIT_GRACE`）。刚敲完的块索引还没跟上，抢着写容易写坏，宁可晚一点
